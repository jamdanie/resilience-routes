# Accessibility

Resilience Routes should be usable by keyboard, mouse, touch, and assistive technology whenever practical.

## Current support

- Keyboard navigation and shortcuts
- Untimed decision mode
- Reduced-motion setting
- Text labels paired with status color
- Responsive layouts
- Semantic buttons and links
- Print-friendly after-action review

## Testing checklist

- Complete a mission using only a keyboard
- Check visible focus indicators
- Test at 200% browser zoom
- Test a narrow mobile viewport
- Test high-contrast display settings
- Verify that color is not the only status signal
- Review headings and controls with a screen reader
- Keep scenario text concise and plain-language

## Future improvements

- User-selectable text size
- Dedicated high-contrast theme
- Captions and transcripts for future audio
- More descriptive network-map alternatives
- Automated accessibility checks in continuous integration
